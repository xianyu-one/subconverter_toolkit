# Mihomo Observer：曳光弹票据

本清单从现有 Phase 6 后端继续推进。每张票交付一个从输入事件到用户可见结果的行为，可交给一个新上下文独立完成；票内按需改 Collector、SQLite、API、测试、文档和界面。`TB-xx` 是稳定依赖标识，不代表数据库、API 或 UI 层。票据是本地计划，尚未发布为远端 issue。

## 共同边界与完成定义

- 只修改 `mihomo-observer/`；不修改仓库其他组件或用户现有的 `lite-online.ini` 改动。一个 Observer 只观测一台指定的 FlClash/Mihomo 客户端。
- 展示**已观测**事实和检查方向，由用户判断分流是否错误；不宣称请求失败、真实 IPv6 回退、精确结束时间或“最佳节点”，不自动改订阅、发起主动探测或记录敏感 URL/载荷。
- 每票需有可复现的输入（受控 Controller 快照或目标平台实测）、从入口到用户可见出口的验收步骤、必要的测试和文档更新。`go test ./...` 与 `go vet ./...` 保持通过；没有真实设备时只能完成标为“模拟验收”的票，不能声称实机通过。
- 各 Agent 使用独立 worktree/分支领取票；同一依赖前沿可并行做，但共享路由、配置或页面壳的改动合入后要重跑受影响的端到端验收。若票内必须改 Schema，先扩展兼容读写并迁移已有数据，再切换读路径，最后清理旧结构；每一步尽量保持程序可运行、数据可回退。不设单独“改数据库层”的横向票。
- 目前 `GET /connections` 每秒轮询、SQLite WAL、小时/日投影、三类证据与 Basic Auth API 已存在；[实现说明](phase-6-implementation.md)记录了未验证的真实 FlClash 字段。以下票据不重做已完成的 Phase 1–6。

## TB-01：Linux Docker 启动并保留观测历史

**行为**：在容器能访问 Controller 的 Linux 环境，用户用示例 Compose 启动 Observer、用管理员凭据读取状态；容器重启后，同一 SQLite 文件中的已观测历史仍可查询。

**阻塞边**：无代码前置；验收需要可运行 Docker 的 Linux 环境。完成后解锁 Docker 交付门槛，不阻塞 UI 票。Windows Docker 不在本票范围；FlClash 回环监听时应采用同机原生 Observer。

**验收**：提供 `Dockerfile`、Compose 示例和持久卷说明；用受控 Controller 发送至少两帧有累计差额的快照，认证的 `/api/dashboard` 显示已观测字节，未认证请求返回 401；重建容器后历史还在且启动前累计值不会重复记账。文档说明容器到 Controller 的可达性及远程 Basic Auth 的 TLS/可信网络要求。不得把 secret 写进镜像或日志。

## TB-02：Windows 原生首次运行

**行为**：用户在 Windows 桌面启动 Observer，连接同机 FlClash 的回环 Controller，以管理员凭据读取到至少一条已观测连接或明确的空快照状态。

**阻塞边**：**外部阻塞**为可运行的 Windows 测试环境；有条件时优先用实际 FlClash，受控本机 Controller 可用于模拟验收。与 TB-01、TB-03 无技术依赖；完成后可参与 TB-11 的 Windows 实机核对。

**验收**：提供可复现的 Windows amd64 构建/运行说明和配置示例；实际在 Windows 启动、退出、重启，并验证 SQLite 文件与认证 API。Controller 关闭、secret 错误时状态可解释且不泄露凭据。只有交叉编译成功不能单独关闭此票。

## TB-03：受保护的 Dashboard 首屏

**行为**：管理员打开浏览器，完成身份验证后看见当前已观测连接数、今日连接数/流量、近期问题数与数据时间；过期连接流显示“未知/上次更新”，不显示伪造的零。

**阻塞边**：无；以现有 Basic Auth API 和受控快照为起点。完成后解锁 TB-04、TB-05、TB-06、TB-09。界面设计应遵循仓库可用的前端设计规范/技能。

**验收**：未认证访问页面和 API 都无法读取观测内容；正常、空快照、尚未采集和过期状态有不同呈现。用两帧受控快照验证首次累计值仅作基线、第二帧增量进入今日流量；页面数值与 API 一致。只需最小导航和中文文本，不预建其余页面的空壳。

## TB-04：采集缺口在浏览器可见

**行为**：Controller 断开、Observer 丢帧或 Observer 重启后，用户从 Dashboard 看见缺口时间和原因；恢复首帧不会让旧连接突然显示为“正常结束”或产生跨缺口流量。

**阻塞边**：依赖 TB-03 的受保护页面和状态入口。完成后解锁完整 MVP 交付门槛。

**验收**：受控 Controller 依次发送连接、断线、恢复快照；页面显示缺口/最后成功采样时间和当前连接数未知状态，详情或 API 中旧连接状态为 `unknown`，全局与目标级流量不补算缺口期间字节。正常连续空帧仍能标记 `absent`，两种情形可区分。

## TB-05：重复连接证据可被阅读

**行为**：同一目标、目标 IP、路径、网络与端口在一个完整小时出现两次相隔至少五分钟的密集连接，管理员在 Problems 看见目标、实际规则/代理链、证据计数和建议检查方向；若另有合格的小流量长连接，可展开其补充证据。

**阻塞边**：依赖 TB-03 的认证与页面导航。完成后解锁 TB-08；不等待域名详情页，证据可在 Problems 内展开。

**验收**：两次各 12 条连接形成一条近期问题；只发生一次峰值时不形成问题。补充小流量长连接须为已不活动且连续可见，并展示样本数、时长/字节门槛。界面写“重复连接迹象”，不写“重试失败”或自动建议 DIRECT；重算后不再成立的近期 occurrence 会撤回。

## TB-06：域名历史能解释当时走过的路径

**行为**：从一个完整域名进入详情，管理员看到 `host`/`sniffHost` 来源、实际规则和链、已知目标 IP/ASN、小时连接与字节趋势；缺失字段显示未知。

**阻塞边**：依赖 TB-03 的认证页面壳。完成后解锁 TB-07、TB-08、TB-10。

**验收**：受控快照覆盖仅 `host`、仅 `sniffHost`、IP/ASN 后到及两条不同规则路径；详情按实际观测路径区分并保留历史小时归属。连接缺口在趋势中标示，不能画成零。查询主要读聚合数据，不让浏览器请求巨大 raw 表；原始记录仍在保留期时可显示有限的证据细节。

## TB-07：IP-only 目标不会从历史中消失

**行为**：只有目标 IP、没有 `host`/`sniffHost` 的连接，用户仍能在目标列表/详情找到该 IP 的趋势、路径和已知 ASN；若后续同一连接出现域名，详情说明归组发生了变化。

**阻塞边**：依赖 TB-06 的目标详情入口与趋势组件。完成后解锁完整 MVP 交付门槛。

**验收**：受控快照先发 IP-only，下一帧同 ID 补 `sniffHost`；首次累计值不重计，保留期内相关小时统计按已确认域名重新归组，IP 地址维度仍可查。另一条始终无域名的连接只显示 IP，不做反向 DNS 猜测；`destinationIP` 缺失时不借用 `remoteDestination`。

## TB-08：IPv4/IPv6 差异可追溯到可比样本

**行为**：同一域名、域名来源、规则路径、网络与端口的 IPv4/IPv6 观察样本满足门槛后，Problems 出现“值得检查 IPv6 路径”的证据，进入域名详情可核对两侧分子、分母、覆盖小时和趋势。

**阻塞边**：依赖 TB-05 的 Problems 展开/导航和 TB-06 的域名详情。完成后解锁完整 MVP 交付门槛。

**验收**：两侧各至少 20 条、各覆盖两个完整小时且比例达到现有 Phase 5 门槛时出现证据；一侧不足、代理路径不同或存在影响可比性的采集缺口时不出现高把握度结论。界面不用“失败率”“已经回退 IPv4”，只建议检查 IPv6 可达性、DNS AAAA 与实际分流。

## TB-09：代理路径详情保持事实边界

**行为**：管理员选择某条实际观测的规则与代理链，看到其历史连接/流量、承载域名或 ASN，以及关联的问题证据，能回到目标详情。

**阻塞边**：依赖 TB-03 的认证页面壳；可与 TB-04、TB-05、TB-06 并行。完成后解锁完整 MVP 交付门槛。

**验收**：受控快照让同一域名分别经过 DIRECT 与代理链；路径详情分别显示统计和规则载荷，不把链名猜成“最终节点”，也不按速度选最优节点。无 ASN 或代理目录不可得时只显示已知数据；页面与 API 数值一致。

## TB-10：保留期后仍能复盘日历史

**行为**：Raw 达到配置保留期并被清理后，用户仍能从域名详情查看保留中的日统计和当时的问题摘要；界面明确单条连接细节已过期。

**阻塞边**：依赖 TB-06 的域名详情。完成后解锁完整 MVP 交付门槛。

**验收**：用可控时间推进跨日连接、投影与小批量清理；确认 Raw 消失、小时/日统计按各自配置保留，日连接数按 ID 去重且不因清理回退。`daily_stats_days: 0` 表示永久。页面不再声称可查看已清理的原始连接，采集写入在清理期间仍可提交。

## TB-11：实际 FlClash 数据核对

**行为**：在用户实际使用的 FlClash/Mihomo 上访问一个有域名的目标和一个仅有 IP 的目标，Observer 中对应的目标、规则、链、IP 版本与空值状态与脱敏 Controller 响应一致。

**阻塞边**：**外部阻塞**为实际可运行的 FlClash、Controller 可达性和可脱敏样本；Windows 场景还依赖 TB-02 的原生包。此票可在其他 UI 票进行时独立推进，完成后解锁实机验收门槛。

**验收**：记录实际 `/version`、脱敏 `/connections` 前后帧、端口 JSON 类型、`host`/`sniffHost`、`destinationIP`、ASN 与 `chains` 顺序；对照 Observer API/页面逐字段核验。若与官方源码模型不符，在本票内修正解码、持久化、可见结果和回归测试。脱敏样本保留结构与类型，不保存真实域名、IP、进程路径或 secret 到仓库。

## 交付门槛

完整 MVP 的功能门槛是 TB-01、TB-03 至 TB-10；Windows 原生交付还须关闭 TB-02，实机准确性声明还须关闭 TB-11。外部设备不可用时，保留 TB-02/TB-11 的阻塞状态并明确已有模拟验收范围，不把它们默认为完成。后续如出现跨库机械重构，另建一张明确标注的例外票，并按扩展、迁移、收缩分阶段验收。
