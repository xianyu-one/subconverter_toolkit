# Observer 界面与链路地图设计确认稿

状态：用户已确认。本文记录 2026-09-26 的访谈决定及实施范围。

## 目标与交付顺序

分两次交付：

1. 列表排序、分页，以及按目标与时间聚合的链路关系。
2. 实时与历史地图、离线地理定位、界面样式与动画优化。

保留现有浅色仪表盘的信息架构。切页、筛选、悬停和地图状态变化可使用克制的动画；遵守 `prefers-reduced-motion`。

## 列表

- 各列表提供单字段升序或降序，记住该列表上次的排序选择，并可恢复默认。日期趋势默认按时间排列，但表格允许改排序。
- 目标和问题证据等主要列表必须先对完整匹配结果排序，再分页；不能把现有 `LIMIT 200` 的片段在浏览器里重新排序后称为全局排序。
- 详情中的短列表提供可见结果排序；如有截断，应明确说明显示范围。刷新实时数据时保留用户筛选和排序。
- 排序字段须与列表数据有关，数值按数值、时间按时间、文本按本地化规则比较；相同值采用稳定的次级顺序。

## 链路关联与证据等级

- 以每条已观测连接的完整路径为事实，在指定目标和时间范围内聚合连接数与已观测字节，并允许展开路径及连接。多条分支表示不同连接，不表示单条连接同时走多条路径。
- 当前版本 Mihomo 的 `chains` 在原始 API 中按逆于用户阅读的顺序给出；本机样本与 [MetaCubeXD 的反转展示方式](https://github.com/MetaCubeX/metacubexd/blob/main/packages/ui/pages/connections.vue)相符。展示方向为起点至目标，同时保留原始链用于核验。
- 仅凭 `chains` 不一定得到底层 `dialer-proxy` 的实际选择。本机样本中的私有出口关联到 `LoadBalance` 前置节点池，而连接快照只显示出口和上层组；`/proxies` 只给出该池候选名单，没有逐连接的实际第一跳。因此页面区分“已观测路径”“当时候选前置节点”和“具体第一跳未知”。
- 低频读取只读 `/proxies` 并按时间保存代理组关系；查看历史时展示当时最近一次有效的候选名单，缺口或过期时标明未知。候选名单不能当作实际使用记录。
- `remoteDestination`、节点名称、当前组选择或节点池成员均不能单独证明某条历史连接的实际第一跳。

## 地图

- 独立地图页同时提供实时活动连接和历史聚合。历史默认最近 24 小时，可选 7 天、30 天和自定义范围；实时视图约每 2 秒刷新并显示最新有效快照时间。采集断开时显示数据过期与缺口。
- 地图默认按地区聚合，线宽表示已观测字节；可按目标和代理节点筛选并展开完整逻辑链。实时快照与历史累计分开，动画不模拟逐包物理轨迹。
- 地图线表示代理选择的逻辑顺序，不表示真实网络传输路径。各点标明位置来源和精度：城市级、国家级估计、手工指定或未知。国家级点放在示意位置；未知点保留在链路列表中，不臆造坐标。
- 起点从 Observer 配置读取用户预设的国家及省/州；未设置时从第一个可定位点开始。不持久化设备源 IP。
- 目标位置仅由当时已观测到的真实目标 IP 通过离线 GeoIP 估计。缺少目标 IP 时在列表中保留目标与路径，地图上目标位置未知；不重新解析域名来伪造历史位置。
- 节点入口和节点出口分别建模。中转入口所在国家不能冒充境外出口。Observer 可配置节点入口 IP/区域及已知出口 IP/区域；找不到可信出口信息时标为未知。
- Observer 可能与 Mihomo 分机部署，因此不读取 Mihomo 本地运行配置或 provider 文件。[Controller `/proxies` 文档](https://wiki.metacubex.one/en/api/)没有承诺提供节点服务器地址，不能以 API 自动完整定位节点。节点域名若无当时实际 IP 或显式区域配置，地理位置保持未知。
- Observer 通过配置路径读取本机 MMDB，支持国家级或城市级数据；[Mihomo 常用 GeoIP 文件](https://wiki.metacubex.one/en/config/general/)主要用于国家归属，城市坐标需要相应数据库。运行时不向第三方地理服务查询，也不自动下载。浏览器地图底图、脚本、样式和字体均由本地资源提供，不依赖 CDN。数据库缺失时仍能查看未定位的链路。
- 历史连接、链与节点身份按观测时保存。旧日期的地理位置可按当前 MMDB 与当前手工覆盖重新估计，并明确显示“位置为当前估计”及数据库版本/时间。

## 验收场景

1. 目标数超过原来的 200 条时，按总流量或名称排序后翻页，结果仍是完整数据集的正确顺序。
2. `google.com` 的不同连接走不同完整路径时，链路页列出各路径、连接数及流量，路径展开可追溯样本；不会把多个第一跳画作同一连接。
3. 某出口经 `LoadBalance` 前置池拨号时，页面列出历史时点的候选节点，并明确显示逐连接第一跳未知。
4. 对中转节点，已知境内入口和境外出口分别标注；只知道入口时，不把入口画成出口。
5. 断开 Controller、缺失 MMDB、目标 IP 为空、以及节点地址为域名而无实际 IP 时，实时和历史页面均明确显示未知或过期状态。
6. 在阻断互联网但能访问 Mihomo Controller 的环境中，Web UI 地图、字体、脚本及样式照常加载，浏览器和 Observer 不请求第三方地图或地理服务。
