# Phase 5：Analyzer 设计

状态：设计完成，阈值为首版候选默认值，须在 Phase 6 用真实脱敏数据校准。Analyzer 只判断历史记录中是否有值得检查的**异常证据**，不判断订阅配置是否错误，不宣称请求失败或协议回退。[术语](../CONTEXT.md)

## 输入、执行时机与隔离

Analyzer 读取已提交的 `stats_hourly`、`stats_daily`、保留期内的 `connections_raw` 与 `connection_hours`，并查阅 `collection_gaps`。每个完整小时结束后处理该小时的重复连接和小流量长连接迹象；每天在报表时区的日界线后，检查最近 7 个完整日的 IPv4/IPv6 差异。当前未结束的小时仅供详情页查看，不提前生成问题。

小时统计投影完成后才分析相应小时。分析器单独运行，查询设超时和每轮工作量上限；失败只更新自身状态，由下一轮或重启后按 `analyzer_checkpoint` 补算，不影响 Collector。每日重算最近的日窗口和最近 24 个小时窗口，以吸收晚到域名；**只重算原始数据完整覆盖的窗口**。原始数据仅保留 7 天时，七日 IPv6 窗口在完成时分析，过期后不再纠正；默认保留 14 天可提供额外修正空间。超过原始记录保留期的历史问题只展示已保存的证据摘要，不声称可以重新计算分钟级判断。停机超过保留期后无法补算的窗口标为未分析。

分析单位为已观测连接 ID；同一连接在多个小时出现时，小时视图可以有多次贡献，跨日或七天窗口的连接数必须按 ID 去重。所有比例都展示分子、分母和窗口，不使用“失败率”。`connection_hours.observed_active_ms` 是连续采样可见的活动时间，不是精确连接时长；目标级下载字节是连续有效样本的增量，连接原始行的累计字节仍可作为截至最后快照的总量参考。每轮先从新完成的小时汇总筛选候选目标，再按目标与时间索引读取保留期内的原始连接；Web UI 不直接执行这些分析查询。

## 共同门槛与分组

候选分组沿用产品归组：完整 `host`，缺失时 `sniffHost`，再缺失时目标 IP。分析器保存 `target_source`，IP-only 不参与“同域名 IPv4/IPv6”判断。按实际观测的 `route_id` 分开；规则、代理链不同的连接不用于同一路径对比。`network` 和目标端口也分开，避免把不同连接类型混为一组。目标 IP 已知时，重复连接进一步按 IP 分开；目标 IP 未知时只按域名分组，并明确标为“目的 IP 未知”。

缺口与数据质量规则：

1. 与连接的关键观察区间相交的采集缺口，使该连接不能贡献“短连接”或“小流量长连接”的判定；仍可在详情中展示其已知字段。
2. 含大面积缺口、解码错误或写入丢样的分析窗口不生成高把握度问题。缺失 IP、ASN、域名分别按未知处理，不纳入需要该字段的分母。
3. 显示 `eligible_connections`、`excluded_for_gap`、`missing_destination_ip` 等计数；门槛仅作用于合格样本。样本不足时保留统计而不写入 Problems。
4. 候选阈值集中在 Analyzer 配置并随证据版本保存。配置变化后重新分析仍在原始数据保留期内的窗口；旧证据保留原版本与当时的阈值。

## 首版三类证据

以下数值是**候选默认值**，不是网络质量标准；它们用于控制首版误报，Phase 6 应根据实际 FlClash 数据检验后确定。Web UI 总是展示实际计数和阈值。

| 证据 | 候选判定 | 不能据此推断 |
| --- | --- | --- |
| 短时重复连接 | 同一目标、目标 IP（若有）、路径、网络和端口，在 60 秒内首次出现至少 12 条已观测连接；同一完整小时内至少出现两个相隔 5 分钟以上的高密度分钟，才形成问题记录 | 浏览器是否重试、请求是否失败、并发连接是否不正常 |
| 小流量长连接 | 连接在连续有效快照中的可见活动时间至少 10 秒、至少 5 个有效样本、最后累计下载不超过 8 KiB，且该小时同一目标和路径至少有 3 条这样的连接；**只有同时存在短时重复连接证据才进入 Problems** | 握手慢、服务器卡顿；WebSocket、SSH、Streaming 或 Keepalive 是否异常 |
| 疑似 IPv6 路径问题 | 在最近 7 个完整日内，同一域名、域名来源、路径、网络与目标端口下，IPv4/IPv6 各至少 20 条合格连接，且各覆盖至少 2 个小时；IPv6 的“重复/小流量长连接迹象占比”至少 30%，比 IPv4 高至少 20 个百分点且至少为其 3 倍。分母为各地址族的已观测合格连接数 | IPv6 失败率、真实超时、同一请求由 IPv6 回退 IPv4 |

重复连接的分钟计数使用不同连接 ID 的 `first_seen_at_ms`，不把同一连接的多个快照重复计数。连接首次观测可能晚于 API 开始时间，尤其在缺口之后；窗口只以 Observer 首次见到它的时刻计数，并附采样限制。正常网页并发加载也可能达到密度门槛，所以单独的重复连接证据只给较低严重程度。

小流量长连接仅以**已不再活动且未跨缺口**的连接作为候选，避免当前正在正常等待的长连接持续报警。`last_seen_at_ms - first_seen_at_ms` 不是精确时长；门槛使用 `connection_hours` 累计的连续可见活动时间。即使条件满足，也只是重复连接问题的补充证据，不单独归因于网络慢。

IPv4/IPv6 对比只适用于有域名且目标 IP 有效的连接。比较时保持路径、网络、端口和域名来源一致；代理路径不同则分别展示，不归因于 IP 版本。IPv4 迹象占比为零时，只检查 IPv6 的最小占比与绝对差异，非零倍数条件视为满足，不进行除零运算。短时间内先看到 IPv6、后看到 IPv4 可以作为时间线注释，但不计入触发门槛，因为浏览器并行建连也可能产生同样顺序。没有两侧足够样本时只显示观察数据。

ASN 与代理路径在首版是筛选和说明维度，不单独触发“ASN 故障”或“节点更慢”的结论。ASN 缺失不阻止域名/IP 迹象分析；Dashboard 的异常 IP/ASN 数量从问题证据关联的已知 IP/ASN 去重得到，不暗示对每个 IP/ASN 另做了故障判定。

## 严重程度、把握度与展示

不输出 0–100 分。`severity` 是排序用的离散等级：1 表示单一重复连接迹象，2 表示重复连接同时伴随小流量长连接，或达到 IPv6 差异门槛；3 需要多种证据并在至少两个独立日期重复出现。它描述**值得检查的程度**，不是故障概率。

`confidence` 同样分 1–3，表示证据支撑程度，不是统计学上的成功/失败概率：1 为刚达到最小样本门槛或附近存在少量缺口；2 为样本至少达到门槛的两倍且相关时间段没有缺口；3 为样本至少达到门槛的三倍、跨至少两个日期重复出现且相关时间段没有缺口。若窗口数据不完整到无法解释分母，则只显示观察数据，不创建问题。界面同时写出使严重程度和把握度成立的具体计数。

Problems 每个完整主机名或 IP 占一行，取该目标最近 7 天仍出现的最高严重程度、把握度和最近证据时间排序；详情展开每个路径、端口、网络与证据窗口。过去出现但最近 7 天未再出现的记录归入历史，不自动标记“已修复”。建议文字仅指向检查方向：例如 IPv6 路径/DNS AAAA、当前分流规则与代理链、Sniffer/域名来源。无主动对照数据时不输出“应改 DIRECT”“最佳节点”或可直接应用的规则。

## 问题身份与幂等重算

`problem_records.fingerprint` 由证据类型、目标类型和值、路径、端口和网络组成；重复/小流量迹象还包含已知目标 IP，跨 IPv4/IPv6 的问题不包含单个 IP。编码稳定且不依赖数据库自增 ID。小时证据的窗口是单个完整小时；IPv6 证据使用以每天日界线结束的 7 日滚动窗口。`problem_occurrences` 的实际证据时间来自支持该结论的连接，而不是 Analyzer 执行时间；`problem_records.last_evidence_at_ms` 由有效 occurrence 重算，保证旧问题不会因每日重跑而显得刚刚发生。

同一窗口重算时，Analyzer 先生成完整新结果，再通过低优先级写入请求在一个事务中替换该窗口的旧 occurrence、插入新 occurrence、重算受影响的 problem record，最后推进 `analyzer_checkpoint`。新结果不再支持旧问题时，旧 occurrence 被撤回；若某 problem record 没有有效 occurrence，也一并删除。事务失败时旧结果保持原状，下次重试。证据 JSON 只含白名单指标、阈值、数据质量计数和算法版本，不复制原始 metadata 或 URL。

## 需要在实现阶段验证的场景

- 单次打开复杂网页产生几十条正常连接：重复密度达到门槛，但没有第二个相隔足够时间的窗口，不进入 Problems。
- 同一静态资源反复建立小流量短连接：形成重复连接迹象；若又有多条连续可见的长耗时小流量连接，提高严重程度，但不宣称请求失败。
- 同域名 IPv6 与 IPv4 走不同代理链：只显示分组数据，不生成 IPv6 路径问题。
- 同域名同路径两侧样本充分，IPv6 迹象占比明显高于 IPv4：生成可解释的疑似 IPv6 问题；只有一侧样本或多处缺口时不生成。
- `host` 后到、原始数据重归组：相关小时和七日窗口重算，旧问题被正确保留、更新或撤回。
- Analyzer 中途失败或反复重跑：Collector 继续工作，occurrence 不重复，`last_evidence_at_ms` 不被任务运行时间刷新。

## 取舍与扩展

固定规则、样本门槛和原始计数容易审查与调参；代价是无法自动捕获所有网站的特殊行为。首版宁可漏掉少量低样本问题，也不对缺少请求结果的流量给出确定性诊断。积累真实使用数据后，可在保留现有证据版本的前提下加入历史基线、可解释的分数或受限主动验证；这些能力不改变首版“观察证据由用户判断”的边界。
