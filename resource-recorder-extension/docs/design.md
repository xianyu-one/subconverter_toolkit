# 资源请求记录扩展设计

## 目标与范围

第一版在 Chrome 153 或更高版本中运行，利用浏览器提供的公共后缀查询能力。扩展的目录、术语与核心规则生成逻辑保持浏览器中立，方便以后增加其他浏览器支持。扩展用于在日常浏览中查看记录期间各网页的资源请求，并复制可直接粘贴到本仓库 `rule-list/` 的候选规则；它不直接修改规则文件。

用户在侧边栏手动开始全局记录。开始之前已经完成的请求无法补录；界面提示用户刷新当前页面以记录首次加载。记录持续到用户手动停止，跨标签页和导航继续观察。每次访问的顶层页面单独保留请求；刷新和仅改变 URL 片段仍属于同一网页条目。页面加载后持续发出的请求仍属于该页面。

## 记录内容

- 记录各标签页可观察到的主文档、子文档、脚本、图片、API 等 HTTP(S) 请求，以及 WebSocket 握手；不把握手之后的 WebSocket 消息当作可测量请求。
- 同一 URL 的多次请求分别保留。重定向链的每一跳分别显示，并提供跳转关系。
- 每条记录包含 URL、资源类型、状态或失败原因、请求耗时、声明大小，以及浏览器报告时的实际连接 IP。失败或取消的请求仍显示；缺失的耗时或大小标为未知。
- 请求耗时为开始至完成或失败的时间跨度。声明大小来自可得的响应声明，并非实际传输量。内存缓存、浏览器限制和权限可能造成观察缺口，因此页面上的列表不宣称是完整抓包。[Chrome webRequest 文档](https://developer.chrome.com/docs/extensions/reference/api/webRequest)
- 列表默认显示主机名和路径；展开请求后显示完整 URL（含查询）。URL 只用于本地会话内查看，不上传；复制规则时只取主机名或 IP。

## 查看与保留

侧边栏可查看当前网页，也可从“已记录网页”中选择记录期间访问的任何网页，包括已关闭标签页的结果。侧边栏先展示按请求目标归类的汇总，再展开逐条请求。每组显示请求次数、最慢单次请求、请求耗时合计和已知声明大小合计。合计耗时不表示页面实际等待时间；未知大小不计入大小合计。用户可以按目标搜索，并按耗时或声明大小排序。

网页记录在当前浏览器会话内保留，可在侧边栏切换或手动清除。每个网页最多保留最近 1,000 条请求，最多保留最近 50 个网页。超出上限时淘汰最旧条目并提示；存储预算将尽时按最旧请求淘汰。数据不跨浏览器重启持久化；扩展重载、更新或停用也可能清除会话数据。[Chrome Storage 文档](https://developer.chrome.com/docs/extensions/reference/api/storage)

## 候选规则

| 请求目标 | 默认复制 | 可选复制 |
| --- | --- | --- |
| 域名 `api.shop.example.co.uk` | `DOMAIN,api.shop.example.co.uk` | `DOMAIN-SUFFIX,api.shop.example.co.uk`，以及逐级上溯至 `example.co.uk` 的后缀 |
| URL 中的 IPv4 `203.0.113.7` | `IP-CIDR,203.0.113.7/32` | 无 |
| URL 中的 IPv6 `2001:db8::7` | `IP-CIDR,2001:db8::7/128` | 无 |
| 域名请求报告的实际连接 IP | 域名规则不变 | 次级入口复制该 IP 的 `IP-CIDR` 单地址规则，并标明它可能属于 CDN 或共享地址 |

上级域名选项不得到达 `co.uk` 等公共后缀。只提供上述能够从 URL 主机名或浏览器报告的连接 IP 合理生成的匹配类型。候选规则只包含 `类型,匹配值`，不包含代理策略名。用户可以选择多个目标、逐项调整规则类型和匹配值，再复制多行文本；复制前按最终规则文本去重。扩展不判断用户应将规则放入哪个文件，也不替用户决定分流策略。[Mihomo 路由规则文档](https://wiki.metacubex.one/config/rules/)

## 权限与浏览器边界

第一次开始记录时申请观察所有网站所需的网站访问权限，以便看到页面中的第三方资源。获得权限后仅在用户主动开启的记录期间观察各标签页；权限不足或拒绝时说明记录不完整或无法开始。首版使用 Chrome 侧边栏，后续浏览器的界面与请求观察能力须分别验证。[Chrome webRequest 权限](https://developer.chrome.com/docs/extensions/reference/api/webRequest)、[Chrome Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

## 验收场景

1. 在已加载的页面开始记录，刷新后能看到主文档和第三方资源；重复请求各占一条。
2. 一个请求重定向到另一域名，界面保留两跳并能分别复制规则。
3. 某资源失败或没有声明大小，仍可查看 URL 和状态，大小显示未知。
4. 从 `api.shop.example.co.uk` 复制精确域名规则或选定的后缀规则；不会提供 `co.uk`。
5. 选中多个目标时可以逐项调整并复制去重后的多行规则；不会写入仓库文件。
6. 刷新页面继续归入同一网页；仅改变 `#` 不创建新网页；顶层路径或查询改变则创建新网页，整个记录持续。
7. 在另一标签页打开网页后，其主文档和资源被记录；关闭标签页后仍能从“已记录网页”查看与复制，直到手动停止记录。
8. 达到每页 1,000 条请求或总计 50 个网页后，旧数据按约定淘汰，界面显示发生了淘汰。
